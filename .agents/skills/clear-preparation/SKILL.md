# クリア準備 (Clear Preparation) スキルガイド

本スキルは、ユーザーが「クリア準備」と発言した際、あるいはコンテキストリセット前に、これまでの開発経緯・技術スタック・音声ルール・UIデザイン方針・ファイル構造・および全カリキュラムの進捗状態を**100%漏れなく引き継ぐためのサマリーを作成・記憶するガイド**です。

---

## 📋 継続開発 引き継ぎチェックリスト

セッション引き継ぎ時・クリア準備時に必ず以下の項目を整理・記録してください：

### 1. 🎵 音声再生（TTS）制御ルール
- **メインエンジン**: Google Translate TTS（`https://translate.google.com/translate_tts?ie=UTF-8&q={text}&tl=zh-TW&client=tw-ob`）
- **ボイス仕様**: 台湾華語（`zh-TW`）の女性ボイスで完全統一。
- **お助け母音（呼称母音）の仕組み**:
  - `ㄅ ㄆ ㄇ ㄈ`（唇音） ➔ 母音 `ㄛ` を添えて `bō, pō, mō, fō` と発声。
  - `ㄉ ㄊ ㄋ ㄌ`（舌尖音） ➔ 母音 `ㄜ` を添えて `dē, tē, nē, lē` と発声。
- **音声を100%鳴らすマッピング (`window.ZHUYIN_SPEECH_MAP`)**:
  - `ㄚ`➔`啊`, `ㄛ`➔`喔`, `ㄜ`➔`鵝`, `ㄝ`➔`也`, `ㄞ`➔`愛`, `ㄟ`➔`黑`, `ㄠ`➔`凹`, `ㄡ`➔`歐`, `ㄢ`➔`安`, `ㄣ`➔`恩`, `ㄤ`➔`昂`, `ㄥ`➔`鞥`, `ㄦ`➔`二`, `ㄅ`➔`包`, `ㄆ`➔`撲`, `ㄇ`➔`摸`, `ㄈ`➔`佛`, `ㄉ`➔`刀`, `ㄊ`➔`頭`, `ㄋ`➔`奶`, `ㄌ`➔`老`。

### 2. 🎨 Notion風 UIデザインシステム方針
- **トーン＆マナー**: 白（`#FFFFFF`）と上質なグレー（`#F8FAFC`, `#F1F5F9`）をベースにしたミニマルデザイン。
- **テーマカラー**: 統一されたキーカラー「台湾ブルー（`#0284C7`）」。無駄なグラデーションやカラフルな色乱立は厳禁。
- **タイポグラフィ**: `Google Fonts Inter` ＋ `-apple-system`。
- **UIパーツ**:
  - カプセル型ピルバッジ（`border-radius: 9999px`）
  - 繊細な1pxボーダー（`#E2E8F0`）
  - ホバー時の浮遊シャドウ（`transform: translateY(-2px); box-shadow: 0 12px 24px -4px rgba(15,23,42,0.08);`）
  - 再生中ボイスウェーブ（音波イコライザー）アニメーション連動。

### 3. 📚 カリキュラム設計「子音＋母音スモールステップ方式」
- **絶対ルール**: **「未学習の文字は単語例やクイズに一切出さない」**。
- **ステップ構造**:
  - **1-1** 🗣️ 唇音 (ㄅㄆㄇㄈ) ＋ 🎵 単母音 (ㄚㄛㄜㄝ) 【習った8文字で 八, 爸爸, 媽媽, 婆婆 が読める】
  - **1-2** 🗣️ 舌尖音 (ㄉㄊㄋㄌ) ＋ 🎵 二重母音 (ㄞㄟㄠㄡ) 【既習16文字で 大, 帶, 他, 奶, 老, 頭 が読める】
  - **1-3** 🗣️ 舌根音 (ㄍㄎㄏ) ＋ 🎵 鼻音・そり舌 (ㄢㄣㄤㄥㄦ) 【既習文字で 哥哥, 喝水, 好, 風, 台灣 が読める】
  - **1-4** 🗣️ 舌面音 (ㄐㄑㄒ) ＋ 🎵 介音 (ㄧㄨㄩ) 【既習文字で 雞, 七, 西, 魚 が読める】
  - **1-5** 🗣️ 歯茎音・捲舌音 (ㄗㄘㄙ / ㄓㄔㄕㄖ)
  - **1-6** 5つの声調（四声＋軽声）＆ 注音総合まとめクイズ

### 4. 📂 統一ファイル構造
- **HTML**: `step-1-1.html`, `step-1-2.html`, `step-1-3.html`, ...
- **JS**: `src/js/step1-1.js`, `src/js/step1-2.js`, `src/js/step1-3.js`, `src/js/appData.js`, `src/js/appCore.js`
- **CSS**: `src/styles/main.css`
- **ルール**: `AGENTS.md`

### 5. 🏆 クイズ問題数の最適化・100%全要素網羅ルール
- **絶対ルール**: 各ステップ/ページで習うすべての文字（子音・母音）および主要単語が、クイズ内で1回も漏れることなく「100%完全網羅」される問題数（例: 8文字＋主要単語で計10〜12問など）を、ページの内容量に合わせて動的・適切に設計・実装すること。
- **自動シャッフル**: 繰り返し挑戦時の記憶定着を図るため、問題順序および選択肢の位置を常にランダムシャッフルすること。

### 6. 🚫 Vercel自動デプロイ禁止ルール（ローカル検証限定）
- **絶対ルール**: Vercelなどの外部デプロイコマンド（`npx vercel --prod` や `vercel` 等）はユーザーからの明示的な命令がない限り絶対に使用しないこと。
- **動作検証**: 動作確認や表示チェックはすべてローカル環境（`npm run dev` や `npm run build` 等）のみで行うこと。

### 7. 🤖 全自動・自律進行ルール
- 実装計画時や機能開発時、ユーザーに逐次確認（Proceed待ち）を行わず、コードの作成・修正・動作検証・Gitコミットまで一気に全自動で自律実行する。
