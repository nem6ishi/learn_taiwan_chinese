# 03-ui-design.md: Notion風 UIデザイン ＆ UI表示ルール

1. **Notion風 UIデザイン方針（厳守）**:
   - **トーン＆マナー**: Notionのように「白と上質なグレー（#F8FAFC, #F1F5F9）」をベースにした洗練されたミニマルデザイン。
   - **余白美**: 情報同士の間にゆったりとした美しい余白（Padding / Margin）を配置し、圧倒的に読みやすくする。
   - **視覚アクセント**: アイコンや見出しに親しみやすい「絵文字アイコン (🗣️, 🎵, 💡, 📚, 🏆)」を配置。
   - **繊細な1px枠線とホバーアニメーション**: カードやボックスは繊細な1pxボーダー（`#E2E8F0`）で囲み、マウスホバー時に少しだけ上品に浮き上がるシャドウ（`box-shadow: 0 10px 25px -5px rgba(0,0,0,0.05)`）を適用すること。

2. **「注音:」「ピンイン:」プレフィックスラベルの全廃（視認性優先のシンプルUI）**:
   - 単語カードや例文内で注音符号やピンインを表示する際、「注音: 」「ピンイン: 」といった不要で冗長なラベルテキストは一切付けず、注音符号およびピンイン文字列のみをシンプル・明瞭に表示すること。

3. **Pure Static First ルール（コンテンツ非表示の徹底防止）**:
   - JSの動的 `innerHTML` 描画に依存して学習コンテンツを表示する設計を完全に排除し、すべてのHTMLファイル自体に100%完全な静的HTMLカード（文字・フレーズ・豆知識）をあらかじめ直書きしておくこと。
   - JavaScriptの役割は「画面構築」ではなく、「既存の静的要素への音声再生イベントおよびクイズの付与のみ」と制限すること。これにより、JSのロード遅延やエラーが発生した場合でも、学習コンテンツが画面から消えたり非表示になる事故を100%原理的に防止すること。

4. **実践会話形式（チャット吹き出しUI）と全カード音声ボタン化**:
   - CATEGORY 3 以降の対話学習では、店員（左側）と自分（右側）のロールプレイ会話形式（チャット吹き出しUI）を採用する。
   - 小さなボタンではなく、**吹き出しカード全体（`.chat-bubble-card`）および「別の言い方」サブカードをタップ可能な音声ボタン**（`cursor: pointer`, `:hover` ハイライト）にし、視認しやすい「🔊 聴く」バッジを配置する。
   - 現地で頻出する「💡 別の言い方（ネイティブ表現バリエーション）」がある場合、吹き出し内に独立タップ音声対応のサブカードを積極的に併記すること。
